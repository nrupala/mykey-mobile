# Contributing

## Build and test

```sh
npm ci
npm run typecheck   # strict TypeScript, warnings are failures
npm test            # unit + interoperability suites (vitest)
npm run build       # production build
npm run e2e         # Playwright smoke against the built PWA
```

The interoperability suites are the heart of this repo. Fixtures
under `tests/fixtures/` are **generated by the Python
implementation** (`nrupala/mykey`) — never hand-edit them; regenerate
with `scripts/make_fixtures.py` (see README, “The interoperability
gate”). Any change to `src/vault/` must keep both directions green:

1. this client opens Python-generated Vault v3 + MKBAK fixtures;
2. the Python implementation opens files this client writes
   (`scripts/crosscheck_python.py`), including agent-scope
   enforcement after a client-side save.

## Rules

- **Dependencies are pinned to exact versions.** No ranges, no
  floating installs; `package-lock.json` is committed.
- **Licence headers.** Every source file carries its bucket header
  (see `LICENSING.md`): `src/vault/` format/crypto modules are
  proprietary core; UI/platform/config are Apache 2.0.
- **No network.** The client must stay incapable of network calls:
  CSP `connect-src 'none'`, no INTERNET permission on Android, no
  analytics. A change that needs an exception is a design review,
  not a pull request.
- **Plain words in the UI.** Primary screens use everyday language;
  engineering terms belong in docs, one layer down.
- Pull requests: one workstream per PR, green CI (typecheck, tests,
  cross-check, build, e2e) before merge.
