# MyKey — web client (PWA) + Android app

One TypeScript client for MyKey, the zero-trust password manager,
serving two surfaces from a single source of truth:

- **an installable, fully offline PWA**, and
- **the Android app** (Capacitor wrapping the exact same build).

There is no MyKey server, no account, and no telemetry. The client
makes **no network calls at all** — the Content Security Policy
(`connect-src 'none'`) makes that a property of the code, not a
promise. Your vault is a single encrypted file (Vault v3, the same
format as the desktop engine in `nrupala/mykey`); every device holds
only ciphertext.

The client also tracks **password age**: the day each password was
set lives inside the encrypted vault, passwords come due for a
change after 180 days by default (change the default — or per
entry — or turn it off), and a calm rotation section lists what
needs attention. No notifications yet; no new permissions.

## Architecture

```
src/
  brand.ts            Brand strings — the ONLY place identity lives
                      (mirrors brand.py in the desktop engine).
  vault/              PROPRIETARY core — the Vault v3 format:
    vault.ts            engine: slots, core, entries, bundles, CRUD
    crypto.ts           AES-256-GCM, Argon2id (hash-wasm), PBKDF2
    recovery.ts         BIP-39 phrase keys + backup keypair
    totp.ts             RFC 6238 TOTP
    backup.ts           MKBAK backup packages: export + import (v2
                        two-factor recovery, device + pairing paths)
    pairings.ts         key-value pairing records + backup codes
    device.ts           this client's device / pairing-target keys
    csvio.ts            CSV import/export, mirroring the desktop engine
    encoding.ts         base64 / canonical JSON / strict helpers
    store.ts            IndexedDB — ciphertext + local identity keys
  platform/           Apache-2.0 platform shell:
    biometric.ts        Android Keystore-backed fingerprint unlock
    filesync.ts         File System Access folder sync, share/download
  ui/                 Apache-2.0 interface:
    app.ts              The whole UI — plain DOM, no framework
    themes.ts           Skin token sets (the only colours anywhere)
    appearance.ts       Skin choice: device default, persist, paint
android/              Capacitor-generated Android project (hardened:
                      no INTERNET permission, OS backup disabled)
tests/fixtures/       Vault + MKBAK fixtures GENERATED BY the Python
                      implementation (scripts/make_fixtures.py)
```

The vault core (`src/vault/`) is a faithful port of the Python
engine's file format — same KDF parameters (read from the vault
header, never downgraded), same AAD domains, same entry-hash seal,
same bundle rebuild on save. Unknown core fields round-trip
verbatim, so desktop features the client doesn't surface (agents,
devices, pending entries) survive a save untouched. Brand strings
live only in `src/brand.ts`, over a brand-neutral engine.

## Security model

- **Formats.** AES-256-GCM everywhere; master/recovery slots wrap
  the vault key under Argon2id (3 / 65536 KiB / 4, from the header);
  per-entry data keys; entry ciphertext hashes sealed in the core
  and verified before any entry decrypts. All primitives are
  WebCrypto, `@noble/*`, `@scure/bip39`, or `hash-wasm` (Argon2id
  WASM) — no hand-rolled cryptography.
- **Storage.** IndexedDB holds exactly one thing: the encrypted
  vault file bytes. No plaintext, no keys, no passwords in web
  storage, nothing in logs. Locking zeroes key buffers and drops
  references (best-effort in a GC runtime — stated plainly).
- **Fingerprint unlock (Android, opt-in).** The vault gains one
  extra wrapped slot whose random wrap key is stored in
  Keystore-backed, biometric-gated credential storage
  (`BIOMETRY_ANY`: a fresh biometric prompt per read). The wrap key
  unwraps the vault through the vault's own cryptographic path —
  biometrics alone never expose plaintext, and turning the feature
  off deletes the slot and the stored key. The pure web PWA does
  not offer this (a wrap key in web storage would be a backdoor).
- **Backup packages.** MKBAK export AND restore, enforcing the
  desktop's rules: the source fingerprint is recomputed from the
  package's keys and must match a fingerprint the user supplies
  independently (a package cannot vouch for itself); the Ed25519
  package signature must verify; older-than-last-restored packages
  warn first. Newer (v2) packages open outside the app only with
  the recovery phrase AND an 8-word backup code together — the
  code is shown once at export and never stored. Which targets
  receive a package is decided by key-value pairing (see
  docs/FEATURE_MATRIX.md).
- **Clipboard.** Copied passwords clear themselves after 1 minute
  (you can choose 1–5 minutes in Settings). Only what MyKey put
  there is cleared — copy something else afterwards and it is left
  alone — and locking the vault clears a copied secret at once.
  On Android the clip is marked sensitive, so system previews and
  keyboard history treat it as a secret. On the web, a browser
  that refuses clipboard access without focus can block the
  timed clear; the app never claims a clear that did not happen.
- **Known boundary.** Desktop vaults sealed by the audit log open
  with an on-screen notice: the web client cannot verify the
  sidecar audit log. The seal rides through every save untouched,
  so the desktop's checks apply again on hand-back.
- **Supply chain.** All dependencies are pinned to exact versions;
  the Android manifest ships with **no INTERNET permission** and
  Android cloud backup of app data disabled.

## The interoperability gate (non-negotiable)

A client that only opens its own files is not done. Fixtures in
`tests/fixtures/` are generated by the **Python** implementation:

```sh
# one-time: python env with the engine's deps
python -m venv /tmp/oracle && /tmp/oracle/bin/pip install cryptography argon2-cffi
MYKEY_PY_DIR=/path/to/mykey /tmp/oracle/bin/python scripts/make_fixtures.py

npm test          # TS opens the Python vault + MKBAK; vectors match
MYKEY_PY_DIR=/path/to/mykey /tmp/oracle/bin/python scripts/crosscheck_python.py
                  # Python opens what TS wrote: resaved, modified and
                  # TS-created vaults; agent scope still enforced
npm run e2e       # built PWA: create → add → lock → unlock → offline
```

CI (`.github/workflows/pwa.yml`) regenerates the fixtures from the
Python engine's current `main` on every run and runs the whole
gate, so format drift between the repos fails loudly.

## Android

Local build needs an Android SDK (JDK 21):

```sh
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug bundleRelease
```

Without a local SDK, use **Actions → “Android — debug APK +
release AAB”**, which builds and uploads both artifacts.

Signing, stated plainly: the debug APK carries the standard
Android debug key (device testing only). The release AAB is
**unsigned** — it ships through Play App Signing enrolment, a
human account step. No keystore exists in, or is generated by,
this repository.
